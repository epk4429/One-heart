# 07. 검증 구조 명세

기획안 6쪽 특장점: **"계산과 설명의 분리, 숫자·근거 대조 — 계산값과 AI 답변의 숫자·근거 대조로 신뢰성 확보."** 13쪽: "실제 서비스에서는 계산엔진 결과와 숫자·근거를 대조해 검증."

LLM이 쓴 글이 화면에 나가기 전에 이 단계를 반드시 거친다. 시연에서는 이 단계가 동작했다는 표시를 화면에 보여 준다.

## 1. 네 겹 구조

| 겹 | 이름 | 무엇을 막나 | 방법 |
|---|---|---|---|
| 1 | 자리표시 | LLM이 숫자를 지어내는 것 | 숫자는 `{{fact:ID}}`로만 쓰게 하고(06 공통 규칙), 화면이 엔진 값을 채운다 |
| 2 | 숫자 스캔 | 자리표시 규칙을 어기고 숫자를 직접 쓴 것 | 출력 글에서 숫자 표현을 찾아 허용 목록과 대조 |
| 3 | 근거 대조 | 없는 근거·출처를 대는 것 | 참조 id(fact, 요약 필드, 조건, 온톨로지 노드)가 실제로 있는지 확인 |
| 4 | 산술 일관성 | 합의안 숫자끼리 안 맞는 것 | 분담방식 합계 = 월 저축, 목표금액 = 엔진 목표값 등 규칙 검사 |

## 2. 겹 1 — 자리표시 해석

- 형식: `{{fact:<fact_id>}}`, `{{quote:<quote_id>}}`
- `fact_id`는 현재 `run_id`의 `facts`(05 3절)에 있어야 한다. 없으면 위반 `unknown_fact`.
- `quote_id`는 입력에 들어간 사용자 문장 속 숫자(예: 서연 "집은 1~2년 늦어도 돼")를 서버가 미리 뽑아 둔 목록에서만 쓸 수 있다.
- 화면 출력 시 `display` 값으로 바꾼다(예: `약 4.9년`).

## 3. 겹 2 — 숫자 스캔

자리표시를 채우기 **전** 원문에서 숫자 표현을 찾는다.

- 대상 패턴: 숫자 + 단위(`억`, `만원`, `원`, `%`, `%p`, `년`, `개월`, `세`, `배`, `명`), 그리고 "1억 4,000만원" 같은 복합 표현. 한글 수사(세 가지, 두 분)는 대상 아님.
- 허용: (a) 자리표시 안, (b) quote 목록과 같은 값, (c) 허용 상수 목록(예: "1:1", 고정 질문의 "5년 뒤", 화면 단계 번호).
- 그 밖의 숫자는 위반 `raw_number`. 위반 숫자가 엔진 facts 중 하나와 표시값이 같으면 `raw_number_matching_fact`(경고: 자리표시로 바꿔 통과시킬 수 있음), 다르면 `raw_number_mismatch`(오류).

## 4. 겹 3 — 근거 대조

| 출력 | 확인 |
|---|---|
| 역할 1 `evidence` | message_index가 실제 원문 범위 안 |
| 역할 3 `positions` | member_id가 실제 구성원, 값 0~1 |
| 역할 6 점검표 `reason` | 자리표시 fact가 해당 option_id의 것 |
| 역할 7 약속 `source` | 가리키는 조건(Stance)·기준 문장·수정안·요약이 실제로 존재. **조건 목록의 모든 조건이 약속 하나 이상에 반영**됐는지 |
| 역할 8 `need_ids`·`constraint_ids` | 온톨로지 어휘 목록에 있는 id |
| 화면 근거 표 | `basis[].source`가 금융정보·공동 목표·가정값 표에 실제로 있음 |

## 5. 겹 4 — 산술 일관성 (합의안)

| 규칙 | 신혼부부 예 |
|---|---|
| 분담방식 금액 합계 = 확정 방법의 월 저축 | 175 + 60 = 235 |
| 목표금액 = 엔진 goal.target_amount | 3억 = 30,000 |
| 방법의 수익률·월 저축 = 확정 Option 값 | 235만원 · 4.2% |
| 합의안 결과 문장의 기간 = 확정 run의 fact | 약 4.8년 |
| 노인 가족 자녀 분담 합계 = 자녀 지원액 | 22 + 18 = 40 |

## 6. 위반 처리

1. 위반 목록을 LLM에 돌려주고 **1회 재생성**("다음 숫자는 자리표시로 바꾸세요: …").
2. 그래도 위반이면 해당 문장을 **템플릿 문장**으로 대체한다(예: "{option} 방법은 {fact:hit_years}에 목표에 닿아요."). 템플릿은 역할별로 미리 둔다.
3. 모든 결과를 검증 기록으로 남긴다.

## 7. 검증 기록과 화면 표시

```jsonc
{
  "verification_id": "ver_…",
  "run_id": "run_…",
  "role": 6,
  "checked_numbers": 7,
  "facts_used": ["B.goal_hit_years", "B.monthly_flow"],
  "violations": [],
  "regenerated": false,
  "fallback_used": false,
  "status": "pass"            // pass | pass_after_retry | fallback | fail
}
```

화면(⚠️ 제안): AI 문장 아래 작은 표시 **"숫자 검증 완료 · 계산엔진 결과와 대조 7건"**. 누르면 문장 속 숫자마다 "엔진 값 / 출처"가 펼쳐진다. 심사위원에게 "AI가 숫자를 지어내지 않는다"를 직접 보여 주는 장면이다.

## 8. 테스트

- 골든 출력에 일부러 틀린 숫자를 넣은 문장(예: "약 4.5년")으로 `raw_number_mismatch`가 잡히는지
- 조건 하나를 빠뜨린 합의안으로 겹 3이 잡는지
- 분담방식 합계를 바꾼 합의안으로 겹 4가 잡는지

# 13. 확인 대기: 데이터 이상 기록

> 수집·정리하다 발견한 이상한 점을 모아 둔다. 형님이 나중에 다시 확인한다(2026-11-03 지시).
> 각 항목은 "무엇이 이상한가 / 지금 어떻게 처리했나 / 확인할 것" 순서다.

## 1. 금감원 공시 API (2026-11-03 전 범주 수집)

### 1-1. 연금저축 API 응답 이상
- **무엇이 이상한가:** `annuitySavingProductsSearch`(안내 페이지 테스트 양식에 적힌 이름)를 부르면 응답 형식이 맞지 않는다.
  - 보험 권역(050000): 총 46건이라면서 1쪽에 4건만 오고 2쪽부터 비어 있다. 그 4건도 연금저축이 아니라 "상업용부동산담보대출" 같은 대출 상품이고, 연금 항목(`pnsn_kind` 등)이 없다.
  - 금융투자 권역(060000): 총 297건, 60쪽이라면서 모든 쪽이 빈 목록이다.
  - 응답의 `prdt_div`는 "P"다(적금은 "S").
- **지금 처리:** 수집(`--all`)에서 뺐다. 연금 항목이 없는 응답은 저장하지 않는 검사를 넣었다(`tools/fetch_finlife.py` SANITY).
- **확인할 것:** 금감원 쪽 일시 장애인지 서비스가 바뀐 것인지, 연금저축 공시를 받을 다른 공식 출처(예: 금감원 통합연금포털)가 있는지.

### 1-2. 연금저축 안내 페이지의 요청 주소 오기
- **무엇이 이상한가:** 연금저축 API 안내 페이지의 "요청URL"이 적금과 같은 `savingProductsSearch`로 적혀 있다. 테스트 양식 쪽 스크립트에는 `annuitySavingProductsSearch`가 있다.
- **지금 처리:** 테스트 양식의 이름을 썼다(1-1처럼 응답은 이상함).
- **확인할 것:** 1-1과 같이.

### 1-3. 저축은행의 상품 코드 겹침
- **무엇이 이상한가:** 같은 금융회사가 정기예금과 적금에 같은 상품 코드를 다른 상품에 쓴다. 3건이다.
  - 하나저축은행 240010: 예금 "비대면 하나더넥스트 시니어 회전예금" / 적금 "파란 하늘 정기적금"
  - 진주저축은행 240001: 예금 "정기예금(진주,통영)" / 적금 "정기예금(진주)"(적금 목록에 이름이 '정기예금')
  - 아산저축은행 240019: 예금 "SB톡톡-정기예금" / 적금 "SB톡톡-정기예금"(적금 목록에 이름이 '정기예금')
- **지금 처리:** 상품 ID를 `PRD_<범주>_<회사>_<상품>`으로 바꿔 겹치지 않게 했다. 겹침을 막는 테스트를 추가했다.
- **확인할 것:** 진주·아산 건은 정기예금이 적금 목록에도 들어간 공시 오류일 수 있다.

### 1-3b. 신용대출의 상품 코드 겹침
- **무엇이 이상한가:** 아이엠뱅크 `WR0002F` 하나의 상품 코드에 "마이너스한도대출"과 "장기카드대출(카드론)"이 함께 있다. 대출 종류(`crdt_prdt_type`)만 다르다.
- **지금 처리:** 신용대출은 상품 ID와 금리 행을 대출 종류까지 넣어 구분한다(`PRD_credit_loan_<회사>_<상품>_<종류>`).
- **확인할 것:** 공시 쪽에서 같은 코드를 쓰는 게 의도인지.

### 1-3c. 대출 공시의 빈 항목
- 신용대출(115개): 공시에 한도·중도상환 수수료 항목 자체가 없다. 모두 "확인 필요"로 표시한다.
- 사업자대출: 신용점수 구간 금리가 0(실적 없음)으로 비어 있는 상품이 많다. 공시 평균(`lend_rate_avg`)이나 최저~최고 중간으로 계산하고 "확인 필요"를 붙였다.
- 주담대·전세: 지난달 평균 금리가 비어 있는 옵션이 있다. 최저~최고 중간으로 계산하고 표시한다.
- 사업자대출의 가입조건 세부 요건(`join_deny_detl`)은 대부분 자유 서술이다(신용등급, 지역, 업종). 844개가 "가입조건 확인 필요"다.

### 1-4. 금융투자 권역 금융회사 개요의 공시월이 오래됨
- **무엇이 이상한가:** 금융투자 권역(060000) 금융회사 개요는 7곳이고 공시월이 2020-10, 2021-08이다. 다른 권역은 2026-10이다.
- **지금 처리:** 받은 그대로 저장했다(`S_finlife_company_060000_202108`).
- **확인할 것:** 금융투자 권역 공시가 더 이상 갱신되지 않는지.

### 1-5. 금융투자 권역에는 상품 공시가 없음
- **무엇이 이상한가:** 정기예금·적금·대출 6개 범주 모두 금융투자 권역은 0건이다.
- **지금 처리:** 상품 없음으로 건너뛰었다.
- **확인할 것:** 원래 대상이 아닌 것인지(연금저축만 금융투자에 있을 수 있음, 1-1과 관련).

## 1-6. 공식 안내 페이지 수집(2026-11-03, 4단계)

- **고용24(육아휴직급여):** 화면이 스크립트로만 열려(`javascript:void(0)` 링크) 원문 글을 자동으로 보관할 수 없었다. 육아휴직급여는 이번 묶음에서 뺐다. 법령(고용보험법 시행령) 원문은 법제처 API(인증 필요)로 받을 수 있는지 확인이 필요하다.
- **보금자리론 금리:** 상품 안내 페이지에 금리 숫자가 없고 별도 "금리안내" 페이지에서 매달 바뀐다(공지: "11월 보금자리론 금리 0.10% 포인트 인상"). 지금은 "금리는 매달 공사가 정해요"로만 보여 준다.
- **주택연금 월지급금:** 공사 예시표는 55·60·65·70·75·80세 × 1~12억원 칸만 있다. 그 사이 나이·가격은 직선으로 이어 계산한 추정이고, 화면에 "추정"이라고 쓴다. 정확한 값은 공사 "예상연금 조회".
- **기초연금 소득인정액:** 소득과 재산 환산을 합친 값이라 가족 정보(월 수입)로는 정확히 계산할 수 없다. 늘 "확인 필요"에 방향만 표시한다.

## 1-7. 사람 조건(2026-11-03, 5단계)

- **(2026-11-03 갱신) 1차 출처 확인:** 법제처 웹페이지 본문으로 조세특례제한법(시행 2026-09-18) 제88조의2를 받았다. "65세 이상인 거주자로서 「기초연금법」 제2조 제3호에 따른 기초연금 수급자", 1명당 원금 5천만원 이하, 2028년 12월 31일까지 가입. 아래 2차 자료 내용이 맞았다. 규칙으로 만드는 일(기초연금 판정과 잇기)은 보류(2026-11-03 형님 결정).
- **비과세종합저축(65세 이상, 처음 기록):** 법령 원문(조세특례제한법 제88조의2)을 받을 공식 경로가 없어 확인하지 못했다. 언론·금융사 안내 등 2차 자료로는 **2026년 1월부터 고령자 대상이 "만 65세 이상"에서 "만 65세 이상 기초연금 수급자"로 좁혀졌다**(2025년 세제개편). 그래서 "65세 이상이면 비과세"로 계산하지 않고, 우대 항목 "비과세종합저축 대상 고객"도 판정하지 않는다. 법제처 API(인증 필요)로 원문을 받으면 기초연금 판정(4단계 제도)과 이어 판정할 수 있다.
- **원문 우대가 있는데 공시 최고금리 = 기본금리인 상품 27개:** 예) 스마트저축은행 스마트 아이플러스 정기적금(원문 "자녀 수 3명 이상 우대이율 3.0%", 공시 기본·최고 모두 3.0%). 전에는 택일형으로 보고 조용히 공시값으로 제한했는데, 이제는 needs_check. 목록은 `ontology/conditions.json`에서 issues에 "공시 최고 우대금리가 기본금리와 같음"이 있는 상품.
- **"다자녀"의 기준이 은행마다 다름:** 원문에 숫자가 없으면 3명 기준으로 판정하고 2명이면 "확인 필요"로 둔다(스마트 아이플러스는 우대가 2명부터라 2명도 다자녀로 보는 것 같음).

## 1-8. 검증 묶음에서 본 것(2026-11-03, 6단계)

- **신용대출 115개는 모든 가족·모든 사람에서 '확인 필요만'**: 공시에 한도·중도상환 수수료 항목이 없어서(1-3c). 실제 서비스에서는 다른 출처(금융사 상품설명서)가 있어야 비교가 된다.
- **상품 줄의 약 63%에 확인 필요 표시**: 저축은행 월 한도가 원문에 없는 것, 원문 우대와 공시 최고금리 불일치(1-7)가 대부분.
- **1인 가구는 가족방을 만들 수 없음**: 구성원 2~6명 제한(`llm/family.py` LIMITS). 혼자 사는 청년·고령자가 쓰려면 '가족방' 개념을 넓혀야 한다(서비스 결정).

## 2. 우대조건 원문과 공시 숫자가 맞지 않는 상품 (2026-11-02, 은행 권역 확인분)

화면에서는 모두 "확인 필요"로 보이고, 짐작해서 금리를 채우지 않는다. 저축은행까지 넓힌 뒤의 전체 목록은 `ontology/conditions.json`에서 `benefit_status`가 `needs_check`인 것(81개)이다.

| 신한은행 쏠편한 정기예금 | 우대조건 "없음"인데 공시 최고 우대금리가 1.05%p 높음 |

| 신한은행 신한My플러스 정기예금 | 원문 우대 최고 0.2%인데 공시는 0.75%p 높음 |

## 3. 아직 사람이 원문으로 확인하지 않은 범위

- 저축은행 정기예금·적금 673개의 우대조건은 **공시 숫자 대조만** 거쳤다. 원문을 읽고 적은 정답 사례는 은행 상품 12개뿐이다(`tests/test_conditions.py`).
- 우대 항목의 종류 분류(예: 이 항목이 '카드'인지 '주거래'인지)는 정답 사례 밖에서는 사람이 다 보지 않았다.

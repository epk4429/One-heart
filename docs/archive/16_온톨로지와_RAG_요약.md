# ONE-Heart 온톨로지와 RAG 요약

> 외부 설명용 요약본이다. 구현·검증의 상세 내용은 `15_온톨로지와_RAG_이해하기.md`를 참조한다. (2026-11-04 코드 기준)

## 1. 개요

**온톨로지는 판단을, RAG는 설명과 근거를 담당한다.** 금융 판단은 AI가 임의로 하지 않고, 공식 원문을 바탕으로 만든 규칙(온톨로지)과 계산 엔진이 수행한다. AI는 가족이 합의한 내용을 규칙이 처리할 수 있는 형태로 변환하는 역할만 하며, 판단의 근거는 RAG가 공식 원문을 그대로 찾아 제시한다.

| 구분 | 온톨로지 | RAG |
|---|---|---|
| 정의 | 금융 지식을 개념 간 관계와 규칙으로 정리한 지식 구조 | 공식 원문에서 관련 부분을 검색해 그대로 보여 주는 장치 |
| 역할 | 합의 사항에 맞는 상품 유형 도출, 가족의 제도 대상 여부 판정, 목표 적합도에 따른 상품 비교 | 해당 제도·법령의 공식 문서 내용을 근거로 제시 |

## 2. 설계 배경

- **AI의 결정 대행 방지**: AI가 상품을 직접 고르면 근거 없는 답이 나올 수 있다. 상품 선택은 규칙이 수행하고 결정은 가족이 한다.
- **판단 과정의 설명**: 합의 사항 → 금융 니즈 → 상품 유형으로 이어진 도출 경로가 곧 "왜 이 상품인가"에 대한 설명이 된다.
- **검수 인력 부재 대응**: 모든 규칙에 원문 인용을 붙이고 자동 검사로 정확성을 확인한다.
- **판단과 설명의 분리**: 검색 결과가 부정확해도 자격 판정에는 영향이 없도록, RAG는 법령 원문을 보여 주는 "관련 법령 찾아보기"와 AI의 근거(금융꿀팁 원문 인용)에 사용하며, 온톨로지와 서로 참조하지 않는다.

## 3. 구축 데이터

| 데이터 | 출처 | 산출물 | 쓰이는 곳 |
|---|---|---|---|
| 금융상품 공시 | 금융감독원 "금융상품 한눈에" API (6개 범주, 공시월 2026-10) | 실제 상품 **2,070개**, 우대·한도 규칙, 범주별 금리 통계 | **온톨로지 전용** (상품 비교, 미래 계산의 수익률 값) |
| 공적 제도 안내문 10쪽 | 한국주택금융공사, 주택도시기금, 보건복지부 | 제도 판정 규칙 **8개**(주택연금, 디딤돌, 버팀목, 기초연금 등) | **온톨로지 전용** (제도 판정). RAG에는 넣지 않는다 |
| 금융꿀팁 200선 18편 | 금융감독원 | RAG 검색 단위 **110개** | **RAG 전용** (공동 목표 제안·방법 설계에서 AI가 원문을 인용해 근거를 댐) |
| 서비스 어휘 | 자체 설계 | 금융 니즈 16개, 제약 조건 7개, 상품 유형 21개 | **온톨로지 전용** (합의 사항 → 상품 유형 도출) |
| 법령 7개 | 국가법령정보센터 (기초연금법, 주택도시기금법, 예금자보호법 등) | RAG 검색 단위 **279개** | **RAG 전용** ("관련 법령 찾아보기") |

> 구분 기준: 서버가 ID로 고르고 검사하는 자료는 온톨로지, 원문을 그대로 찾아 보여 주는 자료는 RAG다. 두 쪽은 서로의 ID나 결과를 참조하지 않는다. 한 원문이 양쪽에 쓰이는 경우는 없다.

모든 원문은 수집 시점 그대로 보관하며(변조 확인용 해시값 포함), 모든 규칙·검색 단위가 원문을 참조한다. 전체는 개념(노드) 약 2,850개와 연결(관계) 약 11,000개의 그래프로 구성되며, `/graph.html`에서 확인할 수 있다.

## 4. 구현 방식

### 4.1 온톨로지

```
합의 사항 ─(AI: 정해진 항목으로 변환)→ 금융 니즈 + 제약 조건 ─(코드: 규칙으로 필터링)→ 상품 유형 → 실제 상품·제도
```

1. **AI는 변환만 수행**: 합의 사항("휴직 준비금은 주식에 넣지 않고 따로 둔다")을 정해진 항목(금융 니즈 `육아휴직 기간 생활자금 마련`, 제약 조건 `원금 손실 불가`)으로 변환한다. 항목 목록에 없는 값은 서버가 거부한다.
2. **코드가 판단**: 제약 규칙(원금 손실 불가 → 위험도가 "원금보장"인 유형만 통과)에 따라 적금은 남기고, 혼합형 투자 상품은 "원금 보장 상품이 아님"을 사유로 제외한다.
3. **실제 상품 비교**: 금리 순이 아니라 목표 적합도 순으로 정렬한다. 한도, 가입 자격, 세후 이자(대출은 총 비용)를 계산 엔진으로 비교하며, 가족 정보로 판단할 수 없는 조건은 추정하지 않고 "확인 필요"로 표시한다.
4. **제도 판정**: 원문에서 조건·수치를 추출해 규칙으로 만들고(원문 인용 포함), 가족 정보로 "해당 / 비해당 / 확인 필요"를 판정한다.
5. **서술형 조건의 규칙화**: 상품의 우대조건·가입대상 설명을 금액·유형별 규칙으로 변환하고, 공시된 수치와 대조해 검증한다.

### 4.2 RAG

- **법령과 금융꿀팁**을 색인한다(2026-11-04). 법령은 조문 단위 **279개**, 꿀팁은 □ 절 단위 **110개**이고, 검색은 종류별로 따로 한다. 제도 안내문은 자격 규칙의 출처로만 쓰고 RAG에는 넣지 않는다.
- **AI의 근거 대기**: 공동 목표 제안·방법 설계에서 코드가 가족 정보(대출·전세·투자·나이 등)로 주제를 골라 꿀팁 조각을 찾아 AI에 준다. AI는 받은 조각 안에서만 근거를 대고, 근거마다 조각 글에서 그대로 복사한 원문 인용을 단다. 서버가 조각 ID와 인용이 원문에 글자 그대로 있는지 검사한다.
- **온톨로지와 독립**이다. 검색 단위에 온톨로지 ID를 붙이지 않고, 온톨로지 코드를 부르지 않는다. 법령마다 색인할 조문의 범위(예: 매우 큰 조세특례제한법은 제87조·제88조의2만)는 RAG가 스스로 정한다.
- 검색 질문에 관련 없는 말이 섞이면 범위를 좁혀 주던 제도 태그가 없어서 법령 조각이 넓게 걸릴 수 있다(관련 없는 질문은 못 찾았다고 답한다).
- 키워드 검색(BM25)에 한국어 조사 처리를 위한 글자 단위 비교를 결합했다. 검색 대상이 수백 건 규모라 의미 기반(벡터) 검색 없이도 충분하다.
- **AI의 요약 없이 원문을 그대로** 제시한다. 법령·제도 문장을 AI가 바꿔 쓰는 과정에서 의미가 달라지는 위험을 없애기 위한 것이다.

## 5. 서비스 활용

| 화면 | 온톨로지·RAG 활용 |
|---|---|
| 4 공동 목표 설정 | 금융꿀팁 원문 조각(RAG)이 AI 제안의 근거가 된다. 근거 문구를 선택하면 인용한 원문과 출처가 화면에서 바로 표시된다. |
| 5 미래 계산 | 예금·적금 수익률 3.3%는 공시 통계를, 주택연금 월 수령액은 주택금융공사 예시표를 반영한다. 제도 대상이 아니면 해당 방법을 제시하지 않는다. |
| 7 상품 비교 | 합의 사항에서 상품 유형까지의 도출 경로("왜 이 상품인가"), 실제 상품의 목표 적합도 비교, 제도 판정 카드, RAG "관련 법령 찾아보기"가 제공된다. |

단계별로 사용할 수 있는 지식의 범위는 서버가 제한한다. **실제 상품·금융회사 이름은 상품 비교 화면에서만** 노출되며, 앞 단계에서 AI가 회사명을 언급하면 서버가 차단한다. 화면 문구는 "추천"이 아니라 "우리 목표에 잘 맞는 순서"이며, 선택과 가입은 가족이 직접 한다.

## 6. 정확성 검증

- **원문 인용 일치**: 모든 규칙·검색 단위의 인용문이 원문에 그대로 존재하는지, 수치가 인용문 안에 있는지 자동 검사한다.
- **공시 수치 대조**: 서술에서 추출한 우대금리 합계를 금융회사가 별도로 공시한 "최고 우대금리 − 기본금리"와 비교한다.
- **가상 가족 12곳 검증**: 신혼, 한부모, 3대 가족, 고령 부부, 자영업 등의 사례로 자격 없는 상품·제도의 노출, 자격 있는 상품·제도의 누락이 없는지 확인한다. 기준 정답은 판정 코드와 별개로 원문을 직접 확인해 작성했다.
- **오류 주입 테스트**: 코드를 의도적으로 잘못 수정한 뒤, 검사가 해당 오류를 실제로 탐지하는지 확인했다.
- **불확실한 조건의 보수적 처리**: 가족 정보로 판단할 수 없는 조건은 단정하지 않고 "확인 필요"로 표시한다.

## 7. 한계

- 보험, 펀드, 모임통장, 연금저축 등은 공시 API에서 제공되지 않아 "데이터 없음"으로 표시한다.
- 공시는 2026-10 기준, 제도 안내문·법령은 2026-11-03에 수집한 개발용 데이터이며, 내용이 변경되면 재수집이 필요하다.
- 인용 일치 검사는 "원문에 해당 문구가 존재함"까지만 보증한다. 해석이 필요한 조건은 "확인 필요"로 처리한다.

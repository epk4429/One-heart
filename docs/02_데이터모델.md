# 02. 공통 데이터 모델

LLM·계산엔진·검증·온톨로지·화면이 주고받는 공통 언어다. PoC는 DB 없이 브라우저 상태(JSON)로 들고 다닌다(⚠️ 9절 제안). 필드 이름은 영어 snake_case, 화면 문구는 한국어.

## 1. 공개 범위 표시

모든 필드에 아래 중 하나를 붙인다. LLM 입력을 만들 때와 화면을 그릴 때 이 표시로 걸러 낸다(`03_보안개인정보.md`).

| 표시 | 뜻 | 누가 보나 |
|---|---|---|
| `self` | 본인만 | 본인, 그리고 본인 데이터를 처리하는 LLM 역할(1·2) |
| `family` | 가족 공유 | 가족방 구성원 전원, 공유 단계 LLM 역할(3~8) |
| `consent` | 본인이 공개를 고른 경우에만 가족 공유 | 공개 전에는 `self`, 공개 후에는 `family` |
| `server` | 서버 전용 | 화면과 LLM에 보내지 않음(API 키, 내부 로그) |

## 2. 엔티티

```
FamilyRoom ─┬─ Member* ─┬─ DisclosureSetting
            │           ├─ Interview (1:1 대화) ─ Clarification*
            │           └─ Summary
            ├─ Story ─ StoryUnderstanding
            ├─ FinancialSnapshot ─ FinancialItem*
            ├─ GoalSetting (공동 목표 설정) ─ Issue*, Proposal, Reply*, Criterion, Approval*
            ├─ SimulationRun* ─ Option*, Result*
            ├─ ConsentRound* ─ Stance*      (합의안 단계의 의사 표시)
            ├─ Agreement (버전*) ─ Commitment*, Signature*
            ├─ AgreementReport
            ├─ Recommendation* (온톨로지 경로 포함)
            └─ ReviewEvent* (지속관리)
```

### FamilyRoom — `family`
| 필드 | 타입 | 예 |
|---|---|---|
| room_id | string | `newly` |
| name | string | 우리 둘의 5년 계획 |
| reason | string | 집을 먼저 살지, 아이를 먼저 가질지… |
| host_member_id | string | `m1` |
| invite_link | string | family-goal.kr/r/… (가상) |
| scenario_type | `newlywed` \| `elder` | |

### Member — `family`
| 필드 | 타입 | 비고 |
|---|---|---|
| member_id, name, initial, role(남편·아내·아버지…), age | | |
| easy_mode | bool | 큰 글씨·음성 |
| identity_verified | bool | 부모님 본인 인증 |
| color | string | 화면 구분색 |

### DisclosureSetting — `self`(설정 자체는 본인만 바꿈)
구성원별로 금융 원본 항목의 공개 여부를 고른다(기획안 11쪽 "보호 정보 / 공유 정보").
| 필드 | 타입 | 비고 |
|---|---|---|
| member_id | string | |
| items | `{financial_item_id: "share" \| "hide"}` | `hide` = 가족·AI에게 낱개로 보이지 않음(공개 / 비공개). 예전 `summary_only`(합계만)는 2026-11-04에 없앴고 저장된 값은 `hide`로 읽는다 |

### Story / StoryUnderstanding — `family`
| 필드 | 타입 |
|---|---|
| story.text, story.author_id | string |
| understanding.family_stage, living, shared_goal, differences | string (LLM 역할 1 출력) |

### FinancialSnapshot / FinancialItem — 항목별 `consent`
| 필드 | 타입 | 비고 |
|---|---|---|
| item_id, owner_id(구성원 또는 `joint`) | string | |
| kind | `deposit` `investment` `real_estate` `loan` `income` `pension` `expense` `transfer` | |
| label | string | 가온은행 예금(가상) |
| amount | number(만원) | 대출·지출은 음수 |
| rate | number(%/년) | 대출 이자, 예금 이자 |
| period | `once` \| `monthly` | 잔액인지 월 흐름인지 |
| source | `mydata` \| `manual` \| `public` | 기획안 6쪽 데이터 3종 |

엔진에 넘길 때는 공개 여부와 무관하게 서버에서 합산할 수 있다(계산은 가족 전체 기준). 단 **화면과 LLM에는** 공개를 고른 항목만 개별로 간다(비공개 항목은 가족 전체 합계에만 들어간다). ⚠️ 이 규칙은 `03` 문서에서 확정.

### Interview — `self`
| 필드 | 타입 | 비고 |
|---|---|---|
| member_id | string | |
| messages | `[{from: "ai"\|"member", text, voice: bool, at}]` | 원문. 공유 단계 LLM에 절대 넣지 않음 |
| fixed_questions | string[3] | "5년 뒤 모습은?" 등 |
| status | `in_progress` `clarifying` `done` `later` | |

### Clarification — `self`
| 필드 | 타입 | 비고 |
|---|---|---|
| word | string | 집을 지킨다 |
| question, easy_question | string | 쉬운 말 재질문 |
| choices | string[] | 큰 글씨 선택지(마지막은 "나중에 답하기") |
| answer | string \| null | |
| resolved_meaning | string \| null | 살아 계신 동안 이 집에 사시는 것 |

### Summary — 확인 전 `self`, 확인 후 `family`
| 필드 | 타입 |
|---|---|
| member_id | string |
| keep | string (꼭 지키고 싶은 것) |
| flexible | string (양보할 수 있는 것) |
| worry | string (가장 큰 걱정) |
| confirmed_by_member | bool |
| clarified | bool (재질문으로 바뀐 경우) |
| extra_notes_count | number (추가 의견 건수만 공개, 내용은 비공개) |

### GoalSetting (공동 목표 설정) — `family`
| 필드 | 타입 | 비고 |
|---|---|---|
| headline | string | 두 분은 가고 싶은 곳이 같아요… |
| agreed_points | string[] | 이미 같은 생각 |
| issues | `Issue[]` | |
| locked_by | `{member_id, word}` \| null | 말뜻 미확인 시 잠금 |
| proposal | `{text, to: member_id[]}` | 1단계 AI 제안 |
| replies | `{member_id: {v: "good"\|"cond"\|"other", text}}` | 좋아요 / 괜찮아요, 단 / 다른 의견. cond·other는 text 필수. 제안 쪽(round)마다 쌓인다(임의결정 88) |
| criterion | string | 2단계 기준 문장 |
| approvals | `{member_id: {approved: bool, comment}}` | |

`Issue`: `{issue_id, title, left_label, right_label, positions: {member_id: 0~1}, gap_level: "small"|"medium"|"large", note}`
- `positions`는 LLM 역할 3의 추정값. 화면은 세 칸(0.34 미만 / 중간 / 0.66 초과)으로만 보여 준다.
- `gap_level`은 코드가 계산(최대−최소 ≥0.6 큼, ≥0.35 보통).

### Option / SimulationRun / Result — `family`
`Option`(계산 조건, LLM 역할 5 출력 = 엔진 입력의 일부. 상세 스키마는 `05_계산엔진.md`)
| 필드 | 예 |
|---|---|
| option_id, label | B, 둘 다 챙기기 |
| description | 계획대로 2년 차에 아이… |
| monthly_saving_breakdown | `[{label:"둘이 버는 돈", amount:700}, {label:"생활비", amount:-350}, …]` |
| expected_return | 3.8 |
| return_basis | `assumption_id` (04 문서의 가정값 표) |
| events | `[{label:"육아휴직", from_month:20, to_month:31, monthly_delta:-150}]` |
| lump_sums | `[{month:6, amount:23000, label:"작은 집으로 옮기고 남는 돈"}]` |
| side_effects | `{child_plan:"2년 차(계획대로)", monthly_slack:75}` |

`Result`(엔진 출력): 목표 달성 월, 월별 현금흐름, 순자산, 해마다 표, 보조 범위(p10/p50/p90, 달성 가능성). 상세는 `05`.
`SimulationRun`: `{run_id, inputs_hash, options[], results[], engine_version, created_at}` — 검증 구조가 이 run_id를 기준으로 숫자를 대조한다.

### ConsentRound / Stance (합의안 단계 의사 표시) — `family`
| 필드 | 타입 |
|---|---|
| round_no | 1, 2… |
| target_option_ids | string[] |
| stances | `{member_id: {option_id: {v: "good"\|"cond"\|"no", text}}}` |
| keep_check | `{option_id: {member_id: {ok: bool, reason}}}` (LLM 역할 6) |
| revision | `{from_option_id, label, changes[], option}` \| null (LLM 역할 5) |
| result | `{final_option_id \| null, conditions: [{member_id, text}]}` |

### Agreement (합의안) — `family`, **버전 관리**
| 필드 | 타입 | 기획안 |
|---|---|---|
| agreement_id, version | string, int | 14쪽 "같은 버전의 합의안을 당사자별로 승인" |
| goal | string | 목표 |
| method | `{option_id, display_label, monthly_saving, expected_return}` | "B. 둘 다 챙기기 · 월 235만원 적립" |
| target_amount | `{value, unit, label}` | **목표금액**: 집 살 때 필요한 우리 돈 3억 |
| contribution | `[{label, amount, unit:"만원/월", payer}]` | **분담방식**: 함께 모으는 돈 175 + 휴직 준비 적금 60 |
| timing | `{type:"condition"\|"date", text}` | **이행시기**: 날짜가 아닌 조건(3억 + 비상금 6개월분) |
| change_conditions | string[] | **변경조건**: 6개월마다, 출산·이직·전세 만료 시 |
| commitments | `Commitment[]` | 약속 1~n |
| next_review | string | 2027년 3월 |
| status | `draft` `signing` `confirmed` | |
| content_hash | string | 서명 대상 확인용 |

`Commitment`: `{commitment_id, text, source: {type:"goal_setting"|"condition"|"revision"|"keep", member_id?}}` — 화면의 출처 표시("서연님 조건" 등)
`Signature`: `{member_id, agreement_version, content_hash, signed_at}` — 버전이나 해시가 바뀌면 서명 무효.

### AgreementReport (합의 리포트) — `family`
기획안 14쪽 "합의 이유·결과·Action Plan".
| 필드 | 타입 |
|---|---|
| reasons | string[] (왜 이 방법인지: 반대 없음, 조건, 점검표 근거) |
| outcomes | `[{label, value_ref}]` (엔진 결과 참조. 숫자를 직접 쓰지 않음, 07 문서) |
| action_plan | `[{when, what, amount_ref?}]` (가족 홈 "이번 달 약속"으로 이어짐) |

### Recommendation — `family`
`{commitment_id, need_id, constraint_ids[], product_type_id, path: [triple…], reason_text}` — 상세는 `08_온톨로지.md`

### ReviewEvent (지속관리) — `family`
`{event_id, kind: "rate_change"|"income_change"|"expense"|"life_event", description, changed_inputs, rerun_id, diff: {before_ref, after_ref}}`

## 3. 상태 저장

- ⚠️ PoC는 `localStorage`에 방 단위 JSON 하나(`oneheart:room:{room_id}`)로 저장한다. 시나리오 초기 데이터는 정적 파일(`/data/scenarios/{room_id}.json`)에서 불러온다.
- "보는 사람"을 바꾸면 화면이 `self` 필드를 그 사람 것만 보여 준다(같은 브라우저 안의 시연용 동작).

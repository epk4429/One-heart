# 05. AI 역할과 검증 구조

> LLM이 맡는 역할(무엇을 보고 무엇을 내는지)과, 그 출력이 화면에 나가기 전에 거치는 검증을 정리한다(2026-11-08 코드 기준).
> 옛 `06 LLM역할`과 `07 검증구조`를 합쳤다. 원본은 `docs/archive/`. 코드: `llm/roles.py`(역할), `llm/pipeline.py`(흐름), `verify/`(숫자 검증), `llm/evidence.py`(근거 인용 검사).
> 할 일은 `00_할일.md`에만 적는다.

## 1. 모든 역할 공통 규칙

| 규칙 | 내용 |
|---|---|
| 모델 | Anthropic `claude-sonnet-5-5`(공식 SDK). 공급자는 환경변수 `LLM_PROVIDER`로 바꾼다(anthropic / replay / hf). 개발용 **재생 공급자**(`llm/replay.py`)는 규칙으로 만든 예시 답을 돌려줘 비용 없이 화면을 확인한다 |
| 생각 깊이 | 역할별 effort: 쉬운 정리(1a·1b·2b·4b·4d·8)는 low, 판단(3·4a·4c·5·5r·6a·6b·7)은 medium |
| 출력 형식 | **JSON만.** 역할마다 서버가 스키마를 검사하고, 틀리면 오류를 붙여 다시 요청한다 |
| 숫자 | 금액·기간·비율을 문장에 직접 쓰지 않는다. 엔진 결과의 fact로 `{{fact:B.goal_hit_years}}`처럼 자리만 표시하고 화면이 엔진 값을 채운다. 없는 fact id를 쓰면 다시 쓰게 한다 |
| 말투·태도 | 존댓말(~요), 쉬운 말. 누가 옳은지 판단하지 않고, 결정하지 않고 제안한다 |
| 입력 경계 | 역할마다 정해진 데이터만 받는다. 입력 조립은 서버 코드가 한다(`07_법규제_개인정보_보안.md` 3.3절) |
| 이름 | 금융회사·상품 이름을 쓰면 실패(G12, 2절). 가족이 쓴 글 속 지시는 따르지 않는다 |
| 대화 기록 | 역할 실행 중 도구 목록을 바꾸지 않고, 재요청 때 이전 응답(생각 블록 포함)을 그대로 붙인다(`llm/runner.py`) |
| 거절 대비 | 안전 분류기가 오탐으로 거절하면 서버 쪽 대체 모델로 자동 재실행 |

| 8 | 온톨로지 매핑 | 7 | 합의안 약속·목표금액·이행시기, 필요·제약 어휘 목록 | 약속마다 필요 id·제약 id·이유 | 어휘 목록 안의 id만, 상품은 고르지 않음(`06_온톨로지와_RAG.md` 3.3절) |

**역할 5의 방법 설계(어떤 가족이든 받기 위해):** AI는 수익률을 가정값 표 id로만 고르고, 있는 매달 항목의 금액 바꾸기·새 월 조정·기간 이벤트·나가는 큰돈을 이유와 함께 낸다(수입 대비 상한). 들어오는 큰돈·주택연금·집 팔기·한 번에 갚기는 코드가 계산하는 **정책 블록**으로만 쓴다. 서버가 가족 숫자·가정값 표·상한과 대조해 매번 검사한다.

**비용:** 한 가족 이용 약 $0.3~0.4(Sonnet 5.5, 2인 15~16회·4인 약 20회 호출, 2026-11-08 실제 확인 신혼부부 $0.371·노인 가족 $0.346).

## 3. 검증 구조

기획안 6쪽 특장점 "계산과 설명의 분리, 숫자·근거 대조". AI가 쓴 글은 화면에 나가기 전에 반드시 이 단계를 거친다. 검증 결과("숫자 검증 완료 · 대조 n건")는 화면에 보이지 않고 서버에서만 한다.

### 3.1 네 겹

| 겹 | 막는 것 | 방법 |
|---|---|---|
| 1 자리표시 | 숫자 지어내기 | 숫자는 `{{fact:ID}}`로만, 화면이 엔진 값을 채움. 없는 fact는 위반 |
| 2 숫자 스캔 | 자리표시를 어기고 숫자를 직접 쓴 것 | 숫자+단위(억·만원·%·년·개월·세 등) 표현을 찾아 허용 목록과 대조 |
| 3 근거 대조 | 없는 근거·출처 | 참조 id(fact, 구성원, 어휘 노드, 금융꿀팁 조각·인용)가 실제로 있는지 |
| 4 산술 일관성 | 합의안 숫자끼리 안 맞음 | 분담 합계 = 확정 방법의 월 저축, 목표금액 = 엔진 목표값 등 |

### 3.2 숫자 스캔의 허용·위반

- 허용: 자리표시 안, 가족이 직접 말한 숫자(예: "1~2년")와 연도, 허용 상수(고정 질문의 "5년 뒤", 단계 번호, '우리 가족 기준' 줄 이름 등).
- 위반: 그 밖의 숫자. 엔진 fact와 표시값이 같으면 **경고**(자리표시로 바꿔 통과), 다르면 **오류**.

### 3.3 근거 인용 검사 (G11)

- 4a·4c·5의 근거는 서버가 준 금융꿀팁 조각 안에서만, 조각 글에서 그대로 복사한 인용과 함께 낸다. 서버가 조각 id와 인용 글자 일치를 검사한다.
- 한계: 인용이 원문에 있다는 것까지만 보증하고, 인용이 주장을 뒷받침하는지는 검사하지 않는다.

### 3.4 위반 처리

1. 위반 목록을 붙여 AI에 다시 생성을 요청한다.
2. 그래도 위반이면 해당 문장을 역할별 **템플릿 문장**으로 바꾸거나 "다시 시도"를 보여 준다.
3. 결과를 검증 기록으로 남긴다(`verification`: 대조한 숫자 수, 쓴 fact, 위반, 재생성·대체 여부, 상태 pass / pass_after_retry / fallback / fail).

### 3.5 테스트

- 틀린 숫자를 넣은 문장이 오류로 잡히는지, 분담 합계를 바꾼 합의안이 겹 4에서 잡히는지(`tests/`).
- 금융꿀팁 인용을 일부러 바꾸면 G11이 잡는지(`tests/test_evidence.py`).
- 실제 흐름 평가: `python -m llm.eval --family newly|elder --max-usd 1.0`(한 번에 하나씩, 비용 상한), 옵션 `--blank-numbers`(목표 숫자를 비움)·`--back-goal`(합의안에서 돌아가기)·`--tag`. 결과 `data/eval/`.

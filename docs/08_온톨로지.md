# 08. 온톨로지 스키마

> 2026-10-31: 이 문서는 상품 추천 층만 다룬다. 서비스 전체 뼈대로 넓히는 설계와 금융 지식 구축 방법은 `12_도메인지식_구축.md`.

- 기획안 15쪽: 가족이 합의한 **금융목표·조건·제약사항** → 금융 Ontology(관계 구조화) → **금융상품 주요 속성: 금리·기간·위험도·유동성·세제혜택·가입조건**.
- 기획안 15쪽: "상품은 유형 예시이며 특정 금융회사 상품이 아님", "최종 선택과 가입은 본인이 결정". 17쪽: **금융상품·정책금융 연결**.
- 역할 분담: LLM(역할 8)은 약속을 **필요·제약 어휘**로 바꾸기만 한다. 상품 유형을 고르는 것은 그래프 탐색 **코드**다. 그래서 추천 경로가 그대로 "왜 이 상품인가요" 설명이 된다.
- 저장: JSON 파일 3개(`/ontology/vocab.json`, `product_types.json`, `rules.json`) + Python 탐색 함수. ⚠️ Neo4j·OWL은 쓰지 않는다(PoC).

## 1. 클래스와 관계

```
Agreement ─hasGoal→ Goal
Agreement ─hasCommitment→ Commitment ─requires→ Need ─satisfiedBy→ ProductType ─hasAttribute→ Attribute
                              └─constrainedBy→ Constraint ─filters→ Attribute 조건
ProductType ⊃ PolicyProgram (정책금융·공적 제도, eligibility 필수)
Need ─forGoal→ Goal            (약속 없이 목표에서 바로 나오는 필요: 예 태아·자녀 보장)
```

| 관계 | 뜻 | 누가 만드나 |
|---|---|---|
| hasGoal, hasCommitment | 합의안 구조 | 합의안 데이터(02) |
| requires, constrainedBy | 약속이 무엇을 필요로 하고 어떤 제약이 있나 | LLM 역할 8 (어휘 안에서만) |
| satisfiedBy | 필요를 채우는 상품 유형 | 온톨로지 정적 데이터 |
| hasAttribute | 상품 유형의 속성 6개 | 온톨로지 정적 데이터 |
| filters | 제약이 속성에 거는 조건 | `rules.json` |

## 4. 탐색 규칙

1. 합의안 약속마다 역할 8의 `need_ids`, `constraint_ids`를 받는다(검증 겹 3 통과 후).
2. Need → `satisfiedBy` 상품 유형 후보.
3. 후보마다 Constraint의 속성 조건을 적용해 거른다. 통과 못 하면 제외 사유를 기록(시연에서 "이 유형은 원금 보장이 아니라 제외했어요"를 보여 줄 수 있음).
4. 남은 유형과 **경로**를 돌려준다.

```jsonc
{
  "commitment_id": "c2",
  "product_type_id": "P_installment_savings",
  "path": [
    ["c2", "requires", "N_leave_fund"],
    ["c2", "constrainedBy", "C_principal_protected"],
    ["c2", "constrainedBy", "C_until_event"],
    ["N_leave_fund", "satisfiedBy", "P_installment_savings"],
    ["P_installment_savings", "hasAttribute", "위험도=원금보장"]
  ],
  "excluded": [{"product_type_id": "P_balanced_fund", "reason": "C_principal_protected"}],
  "reason_text": "약속 2 '휴직 준비금은 따로, 투자하지 않기' → 원금이 줄면 안 되고 출산 전까지 모아야 해서 적금(원금 보장)을 연결했어요."
}
```

`reason_text`는 경로로 만든 템플릿 문장이다(LLM 불필요). 기획안 15쪽 표의 "연결 이유"에 해당한다.

## 5. 기대 결과 (기획안 15쪽 = 정답)

| 합의한 약속 | 연결 상품 유형 | 연결 이유 |
|---|---|---|
| 조건이 되면 집 사기 | 주택청약 저축 · 첫집 대출 | 청약 자격·대출 한도 미리 확인 |
| 휴직 준비금은 따로 | 적금(원금 보장) | 출산 전까지 투자 없이 모으기 |
| 양가 용돈은 같게 | 부부 모임통장 | 자동이체로 함께 확인 |
| (노인 가족) | 주택연금 · 병원비 통장 · 간병 보험 · 신탁 상담 | — |

추가로 화면 7에는 기획안 10쪽의 "태아보험"(목표에서 나온 필요)과 노인 가족 "가족 모임통장"(약속 2)을 둔다. ✅ 노인 가족 모임통장은 넣는다(2026-10-06).

## 0. 왜 하는가 (형님 결정, ✅)

목적: 합의안의 약속(필요)마다 **실제 금융상품과 공적 제도를 공식 근거로 판정·비교해서**, 가족이 "우리 목표에 맞는 길"을 근거와 함께 보게 한다. 온톨로지가 서비스 전체가 기대는 금융 지식 계층이 된다.

1. 온톨로지의 주축은 **실제 금융상품**이다(개발용 스냅샷). 가상 상품 유형 14개는 초기 구현용이었다.
2. 화면은 추천이 아니라 **조건 비교·정보 제공**이고, 선택은 본인이 한다.
   - 다만 금리 순이 아니라 **목표 적합도로 줄 세우고 근거를 보여 준다.**
   - 문구는 **"우리 목표에 잘 맞는 순서예요"**이고, "추천"이라고 쓰지 않는다(금소법 확인 전).
3. **실제 상품 언급은 조건 비교 단계(화면 6)에서만** 한다. 앞 단계(공동 목표·방법 설계)는 재무 원리·제도 종류·범주 통계까지만 쓴다.
4. **제도·법은 RAG**로 둔다. 온톨로지(정형, 판단)와 별개 부품이고, 같은 원문 저장소를 쓴다.
5. **검토자가 없다.** 인용 글자 일치·숫자 일치·공시 숫자 대조·사람(Claude Code)이 원문을 읽은 정답 테스트로 정확성을 담보한다.
6. **실제 서비스 기준으로 만든다.** 예시 가족(신혼부부·노인 가족)은 보여 주기용 예시일 뿐이다. 범위·순서·검증을 예시 가족 기준으로 정하지 않는다.
7. **맞는 상품이 없으면 "없다"고**, 데이터가 없으면 "데이터가 없다"고 이유와 함께 보여 준다.
8. 1단계에서 이상했던 것 등 데이터 이상은 따로 기록만 해 둔다(형님이 나중에 확인) → `13_확인대기_데이터이상.md`.
9. 체험판 HTML(`web/demo.html`)은 mock(재생 공급자) 답으로 바로 응답하고 상품 데이터를 넣는다. 2026-11-03부터 공개 배포에도 들어간다(공개 사이트는 형님만 씀).

## 2. 단계별 기록

### 1단계: 공시 전 범주·전 권역 수집 ✅
- **목적:** 실제 서비스가 만날 상품 전체의 원문을 확보한다.
- **방법:** 금감원 "금융상품 한눈에" 오픈 API의 6개 상품 범주 + 금융회사 개요를 5개 권역(은행·여신·저축은행·보험·금투)에서 받는다.
  - 상품이 없는 권역은 건너뛴다.
  - 응답은 손대지 않고 페이지별로 저장하고 sha256을 남긴다.
  - 인증키는 `.env`의 `FINLIFE_API_KEY`(32자)이고, 파일·화면에 남기지 않는다.
- **결과:** 원본 23개(공시월 2026-10, 4.9MB).
  - 정기예금 436, 적금 337, 주담대 112, 전세대출 58, 신용대출 115, 사업자대출 1,012
  - 금융회사 172곳
- **이상(13 문서):**
  - 연금저축 API 응답 이상(건수와 목록 불일치, 다른 상품)으로 제외
  - 저축은행·아이엠뱅크 상품 코드 겹침 → ID를 `PRD_<범주>_<회사>_<상품>[_<신용대출종류>]`로
  - 금융투자 권역 공시월이 오래됨
- **명령:** `python tools/fetch_finlife.py --all`. 개인 키는 하루 호출 제한이 있어 변환은 저장된 원본으로 한다.

### 2단계: 범주별 비교 기준 일반화 ✅
- **목적:** 상품 종류마다 '좋은 상품' 기준이 달라서, 범주별 비교 계산을 만든다.
- **방법:**
  - **저축형(적금·정기예금):** 받는 돈이 많을수록 좋다.
    - 적금은 매달 넣을 돈, 정기예금은 한 번에 맡길 돈을 입력으로 받는다.
    - 비교 값은 만기 세후 이자(세금 15.4%, `data/assumptions.json interest_tax`)다.
    - 우대조건 규칙(`conditions.py`)에서 "내가 할 수 있는 우대"(action 종류)를 사용자가 고르면 적용 금리를 계산한다. 사람 조건·거래 관계 우대는 금리에 넣지 않고 "해당되면"으로 따로 보여 준다.
    - 월 한도 글을 읽는다("월 가입한도", "최대 불입액", "월부금제한없음" 등).
  - **대출형(주담대·전세·신용·사업자):** 내는 돈이 적을수록 좋다.
    - 보통 받는 금리: 주담대·전세는 맞는 옵션 중 지난달 평균이 가장 낮은 것(없으면 범위 중간, 표시), 신용·사업자는 신용점수 구간(모르면 평균).
    - 한도 글을 비율(집값·보증금 대비)과 최대 금액으로 바꾼다.
    - 중도상환 수수료 글을 고정·변동 요율과 면제 기간으로 바꾼다.
    - 사업자대출은 우대·가입조건도 읽고, 지역 전용(시·군·도 이름)은 확인 필요로 둔다.
  - **계산:** 엔진 `engine/product_math.py`(원리금균등·원금균등·만기일시·일찍 갚기)가 한다. 손계산 대조 테스트가 있다.
  - **순서:**
    - 저축형: 한도 → 받을 수 있는지(자격 불확실) → 세후 이자(1만원 단위) → 확인 필요 → 할 일 수
    - 대출형: 한도 → 받을 수 있는지(지역·자격) → 총 비용(10만원 단위) → 확인 필요 → 금리
- **결과:**
  - 규칙화(예금·적금 773개): 우대금리 verified 668 / capped 24 / needs_check 81
  - 대출 검사 통과: 주담대 70/112, 전세 43/58, 신용 0/115(공시에 한도·수수료 항목 없음), 사업자 74/1,012
  - API `/api/products/fit`이 전 범주를 받는다.
- **파일:** `ontology/products.py`, `conditions.py`, `loans.py`, `fit.py`, `engine/product_math.py`, `tests/test_conditions.py`(정답 사례), `test_loans.py`, `test_fit.py`.

### 3단계: 모든 필요의 길 연결 ✅
- **목적:** 필요마다 실제 상황을 빠짐없이, 솔직하게 보여 준다(몰래 빠진 필요가 없게).
- **방법:**
  - 상품 유형마다 `data`를 단다:
    - real: 공시 실제 상품, `real_category`
    - none: 공시 API에 없음 + 이유. 펀드·모임통장·보험·수시입출금·연금저축
    - program: 제도, `programs` 목록
    - consult: 상담 연결
    - self: 가족이 직접 지킴
  - 새 유형: 정기예금·주담대·전세대출·신용대출·사업자대출·정책 전세자금대출(버팀목)·기초연금
  - 새 필요: 전세 보증금 마련, 사업 자금
  - 연결: 대출 갚기 → 주담대·신용대출(갈아타기 비교), 목표 모으기 → 정기예금, 집 마련 → 주담대
  - 결과 요약(`fit.summarize`) 세 가지:
    - ok: 맞는 상품 있음
    - unsure: 확인 필요만
    - none: 없음
    - 이유와 개수를 함께 보여 준다. 금액을 안 넣었으면 "한도는 아직 따지지 않았어요"라고 말한다.
- **화면 6:** 필요마다 섹션을 만든다. 순서는 길 목록(데이터 없음·상담·직접) → 제도 판정 카드 → 실제 상품 범주별 입력과 순서.
  - 대출 갚기는 가족 대출 잔액을, 전세는 보증금을 미리 채운다.
- **테스트:** `tests/test_routes.py`. 모든 필요에 길이 명시돼 있는지, 실제 상품 길에 데이터가 있는지 본다.
- **골든 매핑 변경:** `data/golden/ontology_mappings.json`. 신혼 c1에 주담대, 노인 c1에 기초연금을 더했다.

### 5단계: 가족 정보로 판정하는 조건 확대 ✅ (2026-11-03)
- **목적:** 지금은 상품 우대조건 중 사람 조건(나이·자녀·무주택·복지 등)을 "해당되면 +x%p(확인 필요)"로만 보여 준다. 가족 정보로 **확실히 판정할 수 있는 것은 판정해서** 적용 금리·자격에 반영한다.
- **할 일:**
  1. 우대 항목 인용에서 숫자 조건을 뽑는다.
     - 나이 범위: "만 19~34세 MZ고객", "만 65세 이상"
     - 자녀 수: "다자녀(3인 이상)"
     - 무주택 등
     - `conditions.py`에 attribute 항목의 조건(var/op/value + quote)을 추가한다.
  2. `fit.py`는 계좌 주인(누구 이름으로)의 나이, 가족 자녀 수, 집 보유로 판정해 met이면 금리에 넣고("해당돼요 +x%p"), 모르면 지금처럼 "해당되면"으로 둔다.
  3. **65세 이상 비과세종합저축:** 공식 출처(법령·국세청 등)로 규칙을 만들고, 해당하면 세후 이자 계산에서 세금을 빼지 않는다. 출처를 못 구하면 하지 않는다.
  4. 소득 기준(서민전용 등)은 추정이라 계속 확인 필요로 둔다(방향만 표시).
- **끝났다는 기준:** 사람 조건 우대가 가족 정보로 판정되면 금리에 반영된다. 판정 근거(인용)를 보여 준다. 테스트가 있다(예: 30세 → MZ 우대 적용, 40세 → 제외).
- **한 일(임의결정 66~68):**
  - `conditions.person_rule`: 우대·가입대상 글 → 판정 규칙 세 종류. 하나로 정할 수 없으면 만들지 않는다(None → 화면은 "해당되면").
    - age: 계좌 주인 나이("만 19~34세", "만 65세 이상")
    - kids: 18세 이하 자녀 수, 명수별 우대 포함("2명 2.0%, 3명 이상 3.0%"). "다자녀"처럼 숫자가 없으면 3명 기준이고, 2명이면 모름
    - flags: 가족이 고르는 조건 7개(임신, 2년 안 출산, 한부모, 장애, 기초생활·차상위, 근로자, 자영업)
  - 판정은 세 값이다.
    - 나이: 확실히 판정한다.
    - 자녀 수: 가족이 "없음·1·2·3명 이상"을 고르면 판정하고, "모름"이면 unknown이다.
    - 고르는 조건: 고르면 met, 안 고르면 unknown이다. **안 골랐다고 '해당 없음'으로 보지 않는다.**
  - 결과: 사람 조건 우대 39개 중 27개가 규칙이 됐다.
  - 판정 안 하는 것(None, 12개):
    - 비과세종합저축(아래), 12·16세 이하·미취학 자녀(자녀 나이를 모름)
    - 중소기업 재직·졸업·특정 통장 보유, 청년층(나이 기준이 원문에 없음)
    - 여러 조건을 나열한 줄, 세대주, 전세사기피해자
  - **가입대상:**
    - 무주택: 넣은 금융정보에 본인·공동 명의 집이 있으면 제외, 없으면 "무주택으로 봤어요"로 표시.
    - 자녀 수 조건이 하나뿐인 가입대상("세명 이상의 미성년 자녀를 둔 부모")도 판정한다.
  - **잘못 빠지던 상품 고침:** 가입대상 "만 18세이하 다자녀를 둔 부모"의 자녀 나이를 가입자 나이로 읽어 **부모가 가입하는 자녀 적금 8개가 부모에게서 빠지던 문제**를 고쳤다.
    - 자녀 나이는 건너뛴다.
    - 부모도 가입하는 상품은 나이 상한을 쓰지 않는다.
    - "기초생활수급자, …, 만65세이상 차상위계층"처럼 여러 대상을 나열한 가입대상은 나이로 빼지 않고 "여러 대상 중 하나"(확인 필요)로 둔다.
  - "비거주 외국인 외 제한없음" 같은 제외 문구는 확인 필요에서 뺐다(40개 상품).
  - **원문 우대와 공시가 어긋나는 상품:** 원문에는 우대가 있는데 공시 최고금리가 기본금리와 같은 상품(27개)이다.
    - 전에는 '택일이라 공시까지'(capped)로 조용히 0%p 처리했다.
    - 이제는 needs_check로 두고, 화면에 "원문대로면 +x%p 더 있지만 공시 최고금리를 넘어서 금리에 넣지 않았어요"라고 쓴다.
  - 화면 6(적금·정기예금):
    - "나에게 해당하는 것" 칸을 둔다(18세 이하 자녀 수 선택 + 조건 7개).
    - 구성원 중 18세 이하가 있으면 자녀 수를 미리 채운다.
    - 해당하면 "해당돼요 · 나이 만 20~39세 +0.5"로 금리에 넣고, 할 일 수에는 세지 않는다.
  - 테스트 `tests/test_person.py` 22개(원문 정답 사례 포함). 전체 160개 통과.
- **안 한 것:**
  - 65세 이상 비과세종합저축 세금 빼기: **보류(2026-11-03 형님 결정).** 처음엔 1차 출처가 없어 못 했고, RAG 작업 때 조세특례제한법 제88조의2 원문을 받아 대상이 "65세 이상 기초연금 수급자"임을 확인했다(docs/13 1-7). 기초연금 판정이 대부분 "확인 필요"라 규칙으로 만들어도 확정 계산이 드물어서 규칙화는 하지 않는다.
  - 가입대상의 대안 나열("하나 이상 충족: 자녀 2명 이상인 부모 / 출산 예정 / 2년 이내 출생")은 판정하지 않고 확인 필요로 둔다.
  - 대출 쪽 사람 조건(사업자대출 우대 등)은 아직이다.

## 4. 정확성 원칙 요약

- 모든 규칙·숫자는 원문 인용이 있고, 인용은 원문에 글자 그대로 있다(G3). 숫자는 인용 안에 있다(G4).
- 예금·적금 우대: 뽑은 합계를 공시 정형 값(최고 우대금리 − 기본금리)과 대조한다(G5 대체). 정답 사례는 사람이 원문을 읽고 테스트로 고정한다(G7).
- 하나로 정할 수 없으면(담보별 요율 여럿, 금액 없는 우대, 추정 소득) 짐작하지 않고 "확인 필요"로 둔다(G8).
- 판정은 met / not_met / unknown 세 가지다. 화면은 "기본 조건은 맞아요(기관 심사 조건은 확인 필요) / 지금은 해당하지 않아요 / 확인이 필요해요".
- 앞 단계 출력에 상품명이 나오면 실패로 처리한다(G12, 2026-11-08 역할 1a·4a~4d·5·5r·6a·6b·7 전체에 구현, 임의결정 89 — 원래 메모: 5·6단계 때 같이).

## 5. 알아둘 함정

- **수정 방법:** 쉘 heredoc 안의 파이썬 패치 스크립트에서 `\n`·`\s` 이스케이프가 여러 번 깨졌다(JS 문자열 줄바꿈, 정규식). 여러 줄 수정은 **Edit 도구**로 하고, 고친 뒤 브라우저(`/demo.html`)로 JS가 열리는지 확인한다(이 PC에 Node 없음).
- **JSON 저장:** `json.dump`로 다시 쓰면 기존 파일 형식이 통째로 바뀐다. 손으로 정리된 파일(`data/assumptions.json`, `data/golden/*.json`)은 글자 단위로 고친다.
- **체험판:** `web/demo.html`은 빌드 결과물이다. `app.js`·온톨로지를 바꾸면 `python tools/build_demo.py`를 다시 돌린다. 체험판의 AI 문장은 재생 공급자(`llm/replay.py`)의 mock이라 다시 녹화할 일이 없다.
- **배포:** 2026-11-03부터 Vercel 묶음에 `ontology/products/*.json`, `knowledge/sources/index.json`·`docs/*.txt`, `knowledge/rag/chunks.jsonl`이 들어가고 실제 상품 비교도 켜진다(`REAL_PRODUCTS=0`이면 끔). 공시 원본 json(`knowledge/sources/S_finlife_*`)은 안 들어간다. 새 데이터 파일을 서버가 읽게 하면 `vercel.json includeFiles`에도 넣는다.
- **예산:** 로컬 AI 사용 누적 약 $6.14로, 로컬 상한 `BUDGET_USD=6.0`(임의결정 30)을 넘었다. 실제 AI를 쓸 녹화·평가는 `python dev_server.py <포트> --budget 6.5`처럼 그 실행에만 올린다(`.env`는 그대로). 형님이 콘솔 월 한도를 걸어 둠 — 반복해서 말하지 않는다.
- **커밋:** 형님이 직접 한다. 2026-11-02 이후 작업(1~4단계, 체험판, 문서)은 아직 커밋 전이다.

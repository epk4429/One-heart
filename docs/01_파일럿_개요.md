# 01. 파일럿 개요

> 2026-11-08 형님 결정으로 목표가 **"모든 가족을 받는 실서비스 체험판" → "두 유형 대상 파일럿"**으로 바뀌었다. 이 문서가 파일럿의 목적·대상·범위의 기준이다.
> 옛 `01 시연대본`(공모전 시연 각본·PoC 범위)은 `docs/archive/`로 옮겼다. 할 일은 `00_할일.md`에만 적는다.

## 1. 목적

- 실제 **신혼부부**와 **노후 준비 가족**이 처음부터 끝까지 써 보게 하고, 끝난 뒤 **서비스 설문**을 받는다.
- 두 유형에서 **깔끔하게** 돌아가는 것이 목표다. 모든 가족 유형을 다 받는 것은 목표가 아니다.
- 범위는 좁히되, 구현 계획(설계 문서·검증·법규제 대응)은 지금까지처럼 탄탄하게 유지한다.

## 2. 대상과 참가 방식

| 항목 | 내용 |
|---|---|
| 대상 유형 | ① 신혼부부(집·아이 계획, 갈등의 성격은 *순서*) ② 노후 준비 가족(부모 + 자녀, 갈등의 성격은 *가치*: 집 = 상속 vs 생활비 재원) |
| 참가자 | 형님의 **지인** 가족 |
| 입력 정보 | 자기 가족의 실제 정보를 **조금 바꿔서** 넣는다. 이름은 별칭, 금액은 대략, 계좌번호·주민번호·주소는 넣지 않는다(`07_법규제_개인정보_보안.md` 3.2절) |
| 진행 | 한 기기에서 '보는 사람'을 바꿔 가며 가족이 돌아가며 입력한다(로그인·여러 기기 없음) |
| 접속 | 공개 주소 + 가족마다 체험 코드 하나(가족별 AI 비용 상한) |
| 목표 카테고리 | 7개 그대로 둔다(내 집 마련 / 목돈 모으기 / 대출 갚기 / 노후·은퇴 / 자녀 계획 / 부모님 부양·간병 / 기타). 대상이 두 유형뿐이라 따로 줄이지 않는다(2026-11-08 형님 결정) |
| 예시 가족 | 기존 두 프리셋(민준·서연 / 노인 가족)은 "예시 가족으로 둘러보기"로 남긴다. 참가 전에 흐름을 보여 줄 때 쓴다 |

## 3. 파일럿 범위

| 구분 | 내용 |
|---|---|
| **그대로 쓴다** | 화면 8단계 전체(가족방 → 우리 가족 이야기 → 각자의 생각 → 공동 목표 설정 → 미래 계산 → 합의안 → 상품 추천(조건 비교) → 가족 홈), 계산엔진, 숫자 검증, 온톨로지·RAG(두 유형이 지나가는 길), 공개 범위 선택, 재점검 |
| **줄인다** | 공동 목표 설정의 AI 제안 핑퐁을 **1번까지만**: AI 제안 → 가족 의견 → (의견이 갈리면) 의견을 반영한 수정 제안 1번 → 그래도 모이지 않으면 '이야기가 필요한 부분' 안내. 2026-11-09 구현(해석은 임의결정 57) |
| **감춘다**(코드는 남김) | 파일럿 대상과 관계없는 기능: 온톨로지 연결 그래프 링크. 목록은 `00_할일.md` 1절. 신용·사업자대출 비교는 두 유형에도 해당될 수 있어 **감추지 않는다**(2026-11-09 형님 결정, 모자란 데이터는 나중에 조사해 채움) |
| **더한다** | 별칭·민감 정보 안내, 체험 끝 안내, 참가자 가족을 받는 공개 사이트 설정(`07` 5절 점검표). 참가 안내·동의·AI 고지는 지인 대상이라 **파일럿 뒤로**(2026-11-09 형님 결정). 개인정보 패턴 차단·'내 기록 지우기' 버튼은 하지 않음(2026-11-10 형님 결정) |
| **안 한다** | 마이데이터 연결, 로그인·여러 기기·알림·각자 서명, 실제 이행 확인, 가입 연결, 다른 가족 유형(1인 가구·한부모·자영업 등) 지원·검증 |

## 4. 성공 기준 (제안)

| 기준 | 확인 방법 |
|---|---|
| 두 유형의 여러 변형 가족이 끝까지 막힘 없이 간다 | 신혼부부·노후 준비 가족 변형 각 3곳 이상을 실제 AI로 끝까지(`python -m llm.eval`) |
| AI 숫자·근거 오류가 화면에 나가지 않는다 | 검증 위반 0, 근거 인용 글자 일치 |
| 앞 단계에 상품·회사 이름이 나오지 않는다 | G12 위반 0 |
| 온톨로지가 두 유형에서 맞게 판정한다 | `python -m ontology.kb_eval`에서 두 유형 계열 가족의 오류 지표 0 |
| 참가자가 설명 없이 이해한다 | 설문(4절)과 관찰 |

## 5. 설문 (계획만, 아직 하지 않음)

2026-11-08 형님 결정: 설문은 계획만 세워 두고 실행하지 않는다. 확정할 때 아래를 정한다.

- **방식:** 외부 설문 도구 + 서비스 마지막 화면(가족 홈)에 링크를 두는 것을 기본안으로 한다. 서비스 안에 설문 화면을 만들지 않는다.
- **묻고 싶은 것(초안):**
  1. 단계별로 이해하기 어려웠던 곳(8단계 중)
  2. 각자의 생각 → 공동 목표 → 합의안 흐름이 실제 합의에 도움이 됐는지
  3. AI 제안·미래 계산 숫자를 믿을 수 있었는지, 근거 보기가 도움이 됐는지
  4. 상품 조건 비교가 쓸모 있었는지, "추천"처럼 느껴졌는지
  5. 가족 중 누가 끝까지 참여했는지, 초대받은 사람이 참여하고 싶었는지(서비스 성립 조건, 옛 CLAUDE.md 7절 🔲)
  6. 다시 쓸 의향, 가격 가설(1회 리포트 19,900원 · 월 9,900원, 기획안 20쪽)
  7. 자유 의견
- **개인정보:** 설문 응답은 체험 데이터와 분리하고 파기 날짜를 정한다(`07` 3.2절).

## 6. 지난 계획과 달라진 점

| 지난 계획 | 파일럿 |
|---|---|
| 공모전 심사위원이 보는 PoC → 어떤 가족이든 받는 체험판 → 실서비스 기준 온톨로지 | 두 유형 대상 파일럿, 지인 참가, 설문 |
| 온톨로지·상품 범위를 서비스 전체 어휘·전 범주로, 검증도 다양한 가상 가족으로 | 만든 것은 그대로 두고, 검증·개선은 두 유형 기준. 범위 밖은 화면에서 감춤 |
| 공개 사이트는 예시 가족만 | 참가자 가족을 받는다(체험 코드 필수) |
| 실제 정보를 넣지 않는 체험판 | 실제 정보를 조금 바꿔 넣으므로 입력 안내와 체험 끝 안내를 갖춘다(동의·고지는 지인 대상이라 파일럿 뒤로 2026-11-09, 패턴 차단·기록 지우기 버튼은 하지 않음 2026-11-10) |
| 공동 목표 핑퐁 3번 | 1번 |
| 법규제는 실서비스 기준 조사 | 파일럿 대응 계획이 본문, 실서비스는 부록 |

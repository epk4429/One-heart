# 01. 시연 대본과 PoC 범위

> **2026-10-06 체험판 전환:** 이 문서의 "각본 재생" 시연은 대체됐다. 지금은 체험자가 자기 가족을 넣고(또는 예시 가족 프리셋을 고쳐) 한 기기에서 돌아가며 입력한다. 흐름·범위는 CLAUDE.md 1·9절, 화면은 `web/js/app.js`, 임의결정 23~32.

- 기준: 최종 기획안(`docs/기획안_발췌.md`, 기능·흐름·숫자) + 프로토타입 v3(`가족금융목표합의서비스_프로토타입_v3.html`, 인물·대사·숫자)
- 표기: ✅ 사용자 확정 / ⚠️ Claude 제안(확인 필요) / 🔲 미정
- 시연 형태: ✅ 사용자가 집에서 혼자, 정상 흐름대로 진행한다(녹화 또는 화면 공유). PC 웹.

## 1. 시연에서 "진짜"가 무엇인지

심사위원에게 보여 줄 핵심 주장은 세 가지다(기획안 6쪽 특장점).

1. **AI가 가족의 말을 읽고 쟁점과 공동 목표를 정리한다** — LLM 실시간 호출
2. **계산은 별도 계산엔진이, 설명은 LLM이 한다** — 엔진이 실제로 계산하고, LLM은 조건을 정하고 해석한다
3. **AI 답변의 숫자·근거를 계산값과 대조한다** — 검증 구조가 실제로 동작한다

그래서 시연 화면마다 아래 셋 중 하나로 표시한다.

| 표시 | 뜻 |
|---|---|
| **진짜** | 시연 중 LLM·엔진·검증이 실제로 호출되어 결과가 그 자리에서 만들어진다 |
| **각본** | 다른 가족의 입력처럼, 정해진 대사를 넣는다(✅ 4절 9번: "시연용" 버튼은 실제 서비스에 없다). 넣은 뒤의 처리는 진짜다 |
| **화면만** | 고정 데이터를 보여 준다 |

⚠️ 원칙: **사람이 입력하는 부분은 각본, AI와 엔진이 처리하는 부분은 진짜.** 그래야 "정해진 결과를 띄운다"는 의심을 피하면서도 시연이 매번 같은 흐름으로 간다.

보는 사람(시연자 시점): 신혼부부는 **서연**, 노인 가족은 **김지은**(방장). 다른 구성원의 입력은 각본이다.

### 화면 2. 우리 가족 이야기 — 진짜(이야기 구조화) + 화면만(마이데이터)

| 항목 | 내용 |
|---|---|
| 시연자 행동 | 이야기 글을 보여 주고 "AI가 이해한 내용"을 실행, "금융 정보 가져오기" → **공개 범위 선택** |

| 기획안 | 11쪽 "각자 입력", "공개 범위 선택"(보호 정보 / 공유 정보) |

### 화면 3. 각자의 생각 — 진짜(요약·재질문) + 각본(다른 가족 대화)

| 항목 | 내용 |
|---|---|
| 시연자 행동 | 보는 사람의 1:1 채팅방에서 AI 질문 3개에 답한다(답은 각본 문장을 붙여 넣거나 직접 입력) → 요약 확인 → 공유 |
| 처리 | 질문 3개는 고정 문구. 답이 들어오면 **LLM 역할 2**(말뜻 재질문)가 애매한 말을 찾고, 대화가 끝나면 **LLM 역할 1**(개인 요약) |
| 핵심 장면 | 노인 가족: 아버님 "이 집이지" → AI가 1:1 재질문 → 큰 글씨 선택지 → "살아 있는 동안 여기서 사는 게 제일" → 요약이 "살아 계신 동안 이 집에 살기"로 바뀜 |
| 다른 가족 | 각본 대화를 시연용 버튼으로 넣고, 요약은 진짜로 생성 |
| 출력 | 구성원별 요약(지키고 싶은 것 / 양보할 수 있는 것 / 가장 큰 걱정), 본인 확인 후 공유 |
| 규칙 | ✅ 대화 원문은 본인만, 가족에게는 본인이 확인한 요약만 |

## 4. 재현 전략: LLM이 매번 같은 숫자를 내게 하려면

기획안 숫자(4.3 / 4.9 / 6.1년 등)는 정답이다. 그런데 선택지 설계(역할 5)를 LLM이 자유롭게 하면 매번 다른 조건이 나와 숫자가 달라진다. ⚠️ 제안:

1. 선택지 설계의 입력에 **"후보 조건 범위"**를 준다. 예: 한 달 모을 수 있는 최대액, 수익률 가정표(예금 비중별), 이벤트(육아휴직 시점별 소득 감소). LLM은 이 안에서 고른다.
2. 금융정보에 **월 저축 내역**(소득·생활비·용돈·여유)과 **방법별 수익률 가정표**, 생애 이벤트(육아휴직 시점·감소액)를 데이터로 넣는다. LLM은 숫자를 새로 만들지 않고 이 값들 중에서 고르고 조합한다.
3. 시나리오 데이터(`04_시나리오데이터.md`)의 **기대 조건(골든 값)**은 **개발 테스트에만** 쓴다. 같은 입력으로 여러 번 호출해 LLM이 골든 조건을 내는 비율을 재고, 안정될 때까지 프롬프트·입력을 고친다. ✅ **화면에는 비교를 표시하지 않는다**(정답을 미리 정해 놓은 것처럼 보이므로). 시연 화면에는 LLM이 낸 조건과 엔진 결과만 나간다.
4. temperature를 0에 가깝게 둔다(구현 3단계 Python 검증에서 확인).
